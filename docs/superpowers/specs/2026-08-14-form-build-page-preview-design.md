# 表单构建：Vue 表单页面预览设计

日期：2026-08-14
状态：已确认并实施

## 背景

表单构建中的预览应反映设计器当前选择的组件，而不是把字段转换成查询区、数据表格和 CRUD 弹窗。用户选择的输入框、下拉框、日期、颜色、按钮及布局容器，需要按设计器中的顺序、栅格和属性直接呈现为可交互 Vue 表单。

## 最终方案

- 顶部“预览页面”打开“表单页面预览”弹窗。
- 预览数据直接来自 `drawingList`，不经过 CRUD 页面模型转换。
- 打开弹窗时深拷贝字段配置，预览输入不会修改设计器中的默认值和属性。
- 复用表单构建现有组件渲染器，保持组件类型、选项、占位符、尺寸、禁用状态和样式一致。
- 递归渲染行容器及其子组件，保留 `span`、`gutter`、`justify` 和 `align`。
- 根据组件的必填和正则配置生成运行态校验。
- 遵循表单属性中的标签位置、标签宽度、尺寸、禁用状态和表单按钮开关。
- 提交仅执行前端校验并提示通过；重置恢复打开预览时的默认值。

## 移除范围

表单构建不再提供 CRUD 业务页预览，因此移除：

- 查询条件、列表字段、新增字段和编辑字段用途开关。
- 功能名称、页面标题、每行列数、详情开关和主键字段配置。
- `drawingList` 到 CRUD `columns + info` 的页面模型转换。

代码生成模块原有的 CRUD 页面预览保持不变。

## 验收标准

1. 图三选择的组件在预览中按相同顺序和栅格显示。
2. 预览内容为图二式 Vue 表单，不显示查询区、表格、分页或 CRUD 工具栏。
3. 下拉、日期、颜色等组件可正常交互。
4. 必填和正则规则可触发表单校验。
5. 关闭预览后，设计器组件配置和默认值不被预览输入污染。
